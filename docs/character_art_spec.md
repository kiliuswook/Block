# 캐릭터 아트 스펙 — 아트 리소스 0장, 코드 렌더링의 한계와 20종 로스터

> 기준: Godot 4.6, 현재 `Player.paint_cat()`(core/scripts/player.gd) 방식(런타임 `_draw()` 절차 렌더링)을 그대로 확장한다.
> 이 문서는 ① 코드만으로 뽑을 수 있는 아트의 기술적 한계, ② 캐릭터 20종 + 각 3단계 업그레이드 외형, ③ 캐릭터별 애니메이션 정의를 다룬다.

---

## 1. 기술 기반 — 쓸 수 있는 도구 (전부 코드, 파일 0개)

현재 게임이 이미 쓰고 있는 것 + Godot이 추가로 제공하는 것:

| 계층 | 도구 | 용도 | 현재 사용 |
|---|---|---|---|
| 벡터 드로잉 | `draw_rect/circle/arc/line/polyline` | 몸통·눈·수염·입 | ✅ paint_cat |
| 폴리곤 | `draw_colored_polygon`, `draw_polygon`(정점별 색 = 그라디언트) | 귀·볼털·왕관 뿔 | ✅ |
| 라운드 박스 | `StyleBoxFlat` (코너 반경·테두리·AA) | 큐브 몸통 | ✅ |
| 베지어 곡선 | `Curve2D` → `tessellate()` → polyline | 꼬리·리본 끈·연기 | ✅ (_paint_tail) |
| 절차 텍스처 | `GradientTexture2D`, `NoiseTexture2D`, `Image`+`ImageTexture` | 털 얼룩·대리석 무늬·후광 그라디언트 | ❌ 미사용 (가능) |
| 셰이더 | CanvasItem shader (코드 문자열로 생성 가능) | 무지개 흐름·용암 발광·투명 일렁임·아웃라인 | ❌ 미사용 (가능) |
| 파티클 | `GPUParticles2D` + `ParticleProcessMaterial` (텍스처 없이 기본 사각/그라디언트) | 불꽃·눈송이·반짝이 트레일 | ❌ 미사용 (가능) |
| 변형 애니메이션 | 노드 `scale/rotation/position` + `sin()` 기반 절차 모션 | 스쿼시&스트레치·꼬리 흔들림 | 일부 |
| 라이트 | `PointLight2D` + 코드 생성 그라디언트 텍스처 | 발광 캐릭터의 주변광 | ❌ (가능, 성능 주의) |

**핵심 아키텍처**: `paint_cat(ci, center, s, look, alive, mouth, skin)` 정적 함수 하나로 인게임·타이틀·도감·리플레이 모두 그린다. 캐릭터 추가 = `skin` Dictionary에 파라미터 추가 + `paint_cat` 내 분기. 이 구조를 유지한 채 `skin.kind`(무늬 종류), `skin.fx`(셰이더/파티클), `skin.stage`(업그레이드 단계)를 추가하는 것이 확장 방향.

## 2. 한계선 — 되는 것 / 조건부 / 안 되는 것

### 2-1. 확실히 되는 것 (현재 수준 ~ 약간 위)
- **플랫 + 라운드 코너 + 단순 그라디언트** 스타일의 큐브/원형 캐릭터. 현재 Cat-Tris 아트가 정확히 이 지점.
- 무늬: 줄무늬(호랑), 얼룩(젖소·삼색), 포인트(샴) — 폴리곤/클리핑(`RenderingServer.canvas_item_set_clip` 또는 몸통 영역 안에서만 그리기)으로 충분.
- 부속물: 귀·꼬리·날개·뿔·모자·목도리 — 이미 액세서리 시스템으로 증명됨.
- 표정: 눈 모양 교체(동그라미/반달/별/하트/졸린 눈), 입, 볼터치, 눈물, 땀방울.
- 발광·오라: 반투명 원 겹치기 + 셰이더 glow.
- 반짝이·파티클 이펙트: 텍스처 없이 `ParticleProcessMaterial` + 코드 생성 `GradientTexture2D`로 가능.
- 애니메이션: 변형(스쿼시&스트레치) + 파라미터(눈 깜빡임, 귀 쫑긋, 꼬리 sin 스윙) 조합으로 **스프라이트 시트 없이 8~10종 상태 애니메이션** 가능. 프레임 아트가 아니라 "파라미터가 시간에 따라 변하는" 방식이므로 오히려 보간이 공짜로 부드럽다.

### 2-2. 조건부로 되는 것 (공수↑ 또는 스타일 타협)
- **털 질감·붓터치 느낌**: NoiseTexture2D + 셰이더로 흉내는 가능하나 "손그림 감성"은 안 나옴. → 이 게임 아트 방향(플랫 키캡 감성)에서는 애초에 불필요.
- **복잡한 유기적 실루엣**(갈기·풍성한 꼬리털): 베지어 곡선 여러 겹으로 가능하지만 곡선 1개당 코드 5~10줄. 캐릭터당 부속물 3~4개가 실용 한계.
- **회전하는 3/4 시점, 옆모습**: 별도 draw 분기를 통째로 다시 짜야 함. 정면 1시점 고정을 강력 권장 (현재도 정면 고정).
- **캐릭터당 렌더 코스트**: draw call 수십 개 수준이라 화면에 수십 마리까지는 문제없음. 셰이더/라이트를 쓰는 캐릭터는 동시 1~2마리(플레이어)로 제한.

### 2-3. 안 되는 것 (이 방식의 진짜 한계)
- **프레임 단위 손맛 애니메이션** (디즈니식 스미어, 모프하는 실루엣) — 절차 변형으로는 대체 불가.
- **디테일 밀도가 높은 일러스트** (장식 갑옷, 세밀한 얼굴) — 도형 수백 개를 코드로 좌표 찍는 건 비현실적.
- **아트 리터칭 반복 작업의 효율** — 코드 수정→실행→확인 루프는 그림 툴보다 느림. `tests/visual_capture.tscn` 스크린샷 루프로 완화하지만, 캐릭터 1종의 "완성 감성" 튜닝에 30분~2시간은 잡아야 함.

**결론: "라운드 큐브 + 무늬 + 부속물 + 이펙트" 문법 안에서는 20종이 아니라 50종도 가능하다.** 차별화는 실루엣(부속물)·무늬·이펙트·모션 개성 4축으로 만들고, 그 문법을 벗어나는 캐릭터(인간형, 세밀 일러스트)는 시도하지 않는다.

## 3. 애니메이션 시스템 — 공통 상태 머신

전 캐릭터 공통 상태 8종. 전부 **변형(transform) + paint_cat 파라미터**로 구현하며 스프라이트 프레임은 없다.

| 상태 | 공통 모션 (기본값) | 구현 |
|---|---|---|
| **Idle** | 숨쉬기: scale.y `1±0.02` sin 1.6s 주기, 3~6초마다 눈 깜빡임(er→0 2프레임), 가끔 귀 쫑긋 | `_process`에서 시간 누적 → paint 파라미터 |
| **Move** | 진행 방향 기울기 5°, 발밑 먼지 퍼프(2~3개 원 페이드), look 오프셋 = 진행 방향 | rotation + 파티클 |
| **Jump** | 이륙 순간 스트레치(scale 0.8x, 1.25y), 상승 중 귀 뒤로 젖힘 | scale 트윈 0.12s |
| **Fall** | 낙하 속도 비례 스트레치, 눈 커짐(er×1.3) | velocity 기반 보간 |
| **Land** | 스쿼시(1.3x, 0.7y) → 0.15s 복원, 착지 먼지 링 | scale 트윈 + 원 페이드 |
| **Dash** | 잔상 3개(위치 큐에 반투명 paint_cat 재호출), 몸 기울기 12° | 최근 위치 링버퍼 |
| **Hurt/Death** | 회색화(DEAD_ 색), X자 눈, 위로 튀었다 낙하 | 기존 구현 유지 |
| **Victory/Escape** | 2회 점프 + 하트/별 파티클, mouth_open | 기존 탈출 연출 확장 |

**캐릭터 개성은 이 8종 위에 "모션 오버라이드 1~2개"만 얹는다** (아래 표의 '개성 모션' 열). 전 상태를 캐릭터별로 새로 만드는 것은 공수상 금지.

## 4. 캐릭터 20종 로스터 — 3단계 업그레이드 외형

업그레이드 = 캐릭터별 키캡 한 바퀴마다 오르는 파츠 해금 단계(`GameState.cat_tier()`)를 그대로 사용한다. 목표는 **단계별 연출을 캐릭터 테마로 교체**하는 것. 공통 규칙:

- **1단계(기본)**: 몸 색 + 무늬 + 기본 얼굴. 부속물 없음.
- **2단계(성장)**: 꼬리 등장 + 테마 소품 1개 + 볼터치 강화. "귀여움이 는다".
- **3단계(전설)**: 실루엣 파괴(오라·이펙트·이중 꼬리 등) + 발광 요소. "화면에서 빛난다".

기존 9종은 색·해금·스탯 유지, 외형 서술만 확정. ✚ = 신규 11종.

- 신규 캐릭터의 해금 조건·스탯은 본 문서 범위 밖 (economy.md에서 별도 설계).

## 5. 구현 순서 제안

1. **공용 모션 레이어** — Idle 숨쉬기/깜빡임, Land 먼지, Dash 잔상을 Player에 공통 구현 (전 캐릭터 즉시 수혜).
2. **skin 스키마 확장** — `pattern`(무늬 종류+폴리곤 데이터), `stage_fx`(단계별 연출 id), `motion`(개성 모션 플래그)을 CATS 딕셔너리에 추가. paint_cat은 데이터 주도로 분기.
3. **난이도 '하' 7종 먼저** (milk, tiger, cow, siam + 기존 cheese/calico/black 단계 연출) — 셰이더 없이 로스터 절반 확보.
4. **공용 셰이더/파티클 모듈 4종** 제작 후 '중' 캐릭터 일괄 처리.
5. **'상' 2종(shadow, rainbow)은 마지막** — 게임의 최고 등급 보상 캐릭터로 배치하는 것이 공수 대비 효과 최대.
6. 각 캐릭터 완성 시 `tests/visual_capture.tscn`으로 3단계×스크린샷 → `.tmp_shots/` 비교 검수.
