# 스팀 출시 준비 — 사용자 작업 체크리스트

> 작성일: 2026-08-28. 코드 쪽 백엔드 작업(GodotSteam 연동)은 **끝났고 실기 검증까지 마쳤다.**
> 남은 건 **Valve 파트너 사이트에서 사람이 해야 하는 일**뿐이다.
> 코드 규칙은 `/steam-backend` 스킬(`.claude/skills/steam-backend/SKILL.md`) 참조.

지금 게임은 **테스트 앱 id 480**(Valve 공개 테스트 앱 "Spacewar")으로 돌고 있다.
리더보드 제출·조회가 실제로 동작하는 상태이고, 진짜 앱 id로 바꾸는 순간 그대로 내 보드가 된다.

```
① 파트너 등록 ($100, 30일 대기)  ──▶ 앱 id 확보  ──▶ [나한테 앱 id 전달]
                                                        ↓
② Auto-Cloud 경로 등록                          내가 app_id 교체 + 확인

                                                        ↓

⑤ 스토어 페이지 (코드와 무관, 별개 트랙)
```

## ① 파트너 등록 → 앱 id

**해야 할 일**

1. https://partner.steamgames.com 가입 (Steam 계정 필요, 개인/사업자 선택)
2. **Steam Direct 수수료 $100** 결제 — 게임 하나당 1회, 매출 $1,000 넘으면 환급
3. 세금 정보(W-8BEN) + 은행 정보 입력 — **이게 제일 오래 걸린다**
4. 결제 후 **30일 대기** (Valve 규정, 이 기간엔 스토어 페이지를 못 올림)
5. 앱 생성 → **App ID** 확인

**⏱ 현실적인 소요**: 서류 통과 며칠 + 대기 30일. **여기가 크리티컬 패스라 제일 먼저 시작할 것.**

**📤 나한테 줄 것**: `App ID` (숫자 하나. 예: `3420000`)

**그러면 내가**: `project.godot`의 `cattris/steam/app_id`를 바꾸고, `tests/steam_check.tscn`으로
실제 보드에 붙는지 확인한다. **코드 수정은 그 값 하나뿐이다.**

> 리더보드는 파트너 사이트에서 미리 만들 필요가 **없다.** 게임이 처음 돌 때
> `findOrCreateLeaderboard`로 알아서 만든다 (`endless`, `classic`, `endless_w2955`…).
> 다만 나중에 스팀 오버레이에서 보드 이름을 예쁘게 보이게 하려면
> 파트너 사이트 → Leaderboards에서 표시 이름만 손보면 된다 (정렬 = 내림차순, 표시 = Numeric).

## ② Steam Cloud (Auto-Cloud) — 세이브 동기화

**코드가 필요 없다.** 파트너 사이트 설정만으로 세이브가 PC 간 동기화된다.

파트너 사이트 → 해당 앱 → **Cloud** → Auto-Cloud 에 아래를 등록:

| 항목 | 값 |
|---|---|
| Root | `WinAppDataRoaming` |
| Subdirectory | `Godot/app_userdata/Cat-Tris` |
| Pattern | `save.json` |
| (한 줄 더 추가) Pattern | `replay_*.dat` |

- 실제 경로 확인용: `%APPDATA%\Godot\app_userdata\Cat-Tris`
- ⚠️ `shader_cache`, `logs`, `vulkan` 폴더는 **동기화하지 말 것** — 위 패턴이 그걸 걸러 준다.
  `*` 하나로 통째로 잡으면 수십 MB 캐시가 클라우드에 올라간다.
- 할당량은 넉넉히(예: 10MB / 파일 100개) 잡아 두면 된다.

> `project.godot`의 `config/name`을 바꾸면 이 경로도 바뀐다. 바꿀 일이 생기면
> Auto-Cloud 설정도 같이 고쳐야 하고, **기존 유저의 세이브가 끊긴다** — 출시 후엔 건드리지 말 것.

**📤 나한테 줄 것**: 없음. 등록만 하면 끝.

## ③ 업적

**코드 쪽 배선은 끝났다** (2026-08-29). `core/autoload/achievements.gd`(autoload `Achv`)가
아래 15개를 정의하고 해금까지 판정한다 — **아래 표의 API Name을 그대로 파트너 사이트에
등록하기만 하면 된다.** id가 한 글자라도 다르면 그 업적만 조용히 무시된다.

- **게임 안에 업적 목록 UI는 없다** — 표시는 스팀 오버레이가 맡는다 (해금 토스트, Shift+Tab → 업적).
  이름·설명·아이콘·13개국어 번역이 전부 파트너 사이트에 있으므로 게임 쪽 번역 작업은 없다.
- 해금 기록은 `save.json`의 `achv` 배열에도 남는다(재해금 방지 + 웹 빌드 진행 보존).
  "게임 초기화"는 이 배열을 **지우지 않는다** — 스팀 업적은 어차피 되돌릴 수 없기 때문.
- 판정은 소급 적용된다: 기존 세이브가 이미 조건을 만족하면 타이틀에 들어가는 순간 해금된다.
- 회귀 테스트: `res://tests/test_achievements.tscn`
- 코드 쪽 규칙(업적 추가 절차·최종 검토 체크리스트·앱 id를 받은 뒤의 검증)은
  `/achievements` 스킬(`.claude/skills/achievements/SKILL.md`)에 있다.

파트너 사이트 → **Stats & Achievements** → Achievements 에서 하나씩 추가.
**API Name(영문 id)이 코드와 정확히 일치해야 한다** — 표시 이름/설명은 자유.

## ④ 빌드 업로드 (SteamPipe)

**해야 할 일**

1. 파트너 사이트 → **SteamPipe** → Depots 에서 depot 확인 (앱 생성 시 자동으로 하나 생김)
2. [Steamworks SDK](https://partner.steamgames.com/downloads/list) 다운로드 →
   `tools/ContentBuilder/` 안의 `steamcmd` 사용
3. 빌드 계정: 본인 파트너 계정으로 바로 올려도 되지만,
   **빌드 전용 계정**을 만들어 두는 쪽이 안전하다 (2FA가 자동화를 막으므로)

**📤 나한테 줄 것**: `App ID` + `Depot ID` (+ 자동화를 원하면 SDK를 어디에 풀었는지 경로)

**그러면 내가**: `tools/`에 익스포트 → `app_build.vdf` 생성 → `steamcmd` 업로드까지
한 번에 도는 스크립트를 만든다. 지금 GitHub Pages 배포 절차와 같은 결로.

> 익스포트 자체는 이미 준비돼 있다: `Steam` 프리셋 → `build/steam/cattris.exe`.
> `steam_api64.dll`은 `.gdextension`의 `[dependencies]`가 exe 옆에 자동 복사한다.

## 나중에 (급하지 않음)

### 주간 리더보드 정리

주간 보드는 주마다 새로 생겨서 **연 104개씩 쌓인다.** 당장은 문제없지만 몇 년 굴릴 거라면
오래된 보드를 지우는 스크립트가 필요하다.

- 파트너 사이트 → Users & Permissions → **Publisher Web API Key** 발급
- Web API `ISteamLeaderboards/DeleteLeaderboard`로 오래된 주차 보드 정리
- 서버가 아니라 **내 PC의 작업 스케줄러**로 주 1회 돌리면 충분하다

**📤 나한테 줄 것**: Publisher Web API Key (이건 **비밀키**다 — 채팅에 붙여넣지 말고
파일이나 환경변수로 두고 "거기 있다"고만 알려줄 것)

### Steam Deck 검증

가로 1920×1080 기준이라 Deck(1280×800)에서 레이아웃이 어떻게 나오는지 확인이 필요하다.
Deck 호환성 심사는 출시 후에도 신청할 수 있으니 급하지 않다.
